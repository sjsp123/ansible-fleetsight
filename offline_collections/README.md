# Offline collection bundle

Pre-downloaded tarballs for this repo's two Galaxy dependencies
(`ansible.posix`, `community.postgresql`), for control nodes that don't
have internet access at deploy time (e.g. an isolated network).

**`redhat.rhel_system_roles` is deliberately not part of this bundle.**
It's used by the opt-in `playbooks/deploy_timesync_role.yml` path (see
[`rhel_system_roles/README.md`](../rhel_system_roles/README.md)), but
it isn't an installable Galaxy collection at all - there's no `redhat`
namespace on public `galaxy.ansible.com` (verified: the Galaxy API
returns zero results, and `ansible-galaxy collection download` fails
with a dependency error). It ships as the `rhel-system-roles` RPM from
RHEL AppStream instead, so it isn't listed in the repo root
`requirements.yml` and can't be added to this tarball bundle by the
`ansible-galaxy collection download` command below - see
`rhel_system_roles/README.md` "Installing the collection" for its own
install path (RPM, or an offline `dnf download --resolve` bundle).

Downloaded with:

```bash
ansible-galaxy collection download -r requirements.yml -p ./offline_collections
```

Contents:

- `ansible-posix-2.2.2.tar.gz`
- `community-postgresql-4.2.0.tar.gz`
- `requirements.yml` — auto-generated by the download command above;
  points at the two tarballs by local filename, not a Galaxy URL.

## Installing from this bundle (no internet required)

From the repo root, on the control node:

```bash
ansible-galaxy collection install -r offline_collections/requirements.yml \
  -p ./collections --offline
```

This installs into `./collections`, the same path this repo's
`ansible.cfg` (`collections_path = ./collections`) already expects — no
different from a normal online `ansible-galaxy collection install -r
requirements.yml`, just reading the tarballs here instead of reaching
out to `galaxy.ansible.com`. `./collections` itself stays gitignored;
only this small tarball bundle is committed.

## Keeping this bundle in sync with requirements.yml

If you ever bump a version in the repo root's `requirements.yml`,
regenerate this bundle to match (needs internet, but only on whichever
machine you run this from — not the eventual offline target):

```bash
rm -f offline_collections/*.tar.gz offline_collections/requirements.yml
ansible-galaxy collection download -r requirements.yml -p ./offline_collections
```

Then commit the updated tarball(s) and `requirements.yml`.
